# Phase 5 pre-implementation audit

- Existing architecture: Express/Mongoose, session authentication/CSRF, owner-scoped services, React/MUI with shared theme/UI primitives. Phase 4 marketDataService owns provider adapters, canonical candles, calendars and caching.
- Frontend: ReplayPage is recorded-trade sequence playback with fill chart, notes and tags; preserve it as a Trade review tab. Reuse Panel, PageHeader, EmptyState, MUI controls and theme. Build a separate SVG candlestick presentation, playback controller and workspace.
- Backend: replayRoutes exposes session and provider status; replayController reads owned trades. Extend with owner-scoped run creation, cursor transitions, events, reveal and screenshots. All market data must come from Phase 4.
- Models: Trade contains real execution time/side/quantity/price, aggregate fields, untimestamped stops/targets/setup/notes, screenshots. Add ReplayRun with independent decisions/annotations/screenshot metadata and private historical snapshots; do not mutate Trade for training decisions.
- Reusable utilities: ownedFilter, ownedPayload, asyncHandler, shared upload root, Decimal, canonical marketDataService, existing backup and isolation conventions.
- Existing tests: Phase 4 normalization/cache/API tests, Replay disclosure theme tests, market-data Playwright scenario, authentication/isolation suites. Preserve legacy review tests and add pure engine/controller/API/workspace/E2E coverage.
- Gaps: no candle replay, server cursor, time-safe projections, indicators, saved decisions or replay artifacts. Candle timestamp currently denotes opening time; add explicit endTimestamp in Phase 4 so a complete OHLC bar is revealed only at close.
- No-leak design: server projections contain only candles closed at/before T; indicators, scales, high/low, executions and artifacts derive only from that prefix. Browser never receives unrevealed candles. Blind mode hides historical overlays/outcomes until explicit completion reveal; scrubbing backwards filters projections again. Untimestamped original annotations are post-review context, not claimed as historical knowledge.
- Likely changes: Phase 4 calendar/canonical candle metadata; Replay routes/controller/service; new model/state/overlay/indicator modules; Replay workspace/chart/controller and client service; backup/ownership registries; tests, E2E scenarios and docs.
- Migration: additive collection/index only. No destructive migration or changes to existing trade/backtest documents. Historical snapshots preserve run context if source trades later change; source candle revision changes require a new run.
- Security: authenticated owner on every run/event/image request, no ADMIN/ROOT bypass, no client timestamps or ownership for decisions, bounded payloads and optimistic version checks. Replay images remain private and cursor gated. Existing rate limits, sessions and CSRF remain.
- Risks: bar-open versus bar-close leakage, future aggregate trade fields, stop/setup fields without knowledge timestamps, concurrent timers/scrubs, stale source revisions, missing ranges, backup ownership, PNG artifact isolation, and rendering large datasets. Explicit limits and tests will cover these.
