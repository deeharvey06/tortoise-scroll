## Proposed smallest coherent scope, pending approval

One selected provider, explicit dated ES contract(s), one agreed canonical live-bar contract and historical overlap/backfill path. Decide whether vendor bars suffice or trades/quotes are required before acquiring tick storage. Record provider event time, receive time, sequence where available, source, contract, session, finality and correction revision. No synthetic gap fill. Unknown/stale/correcting must be explicit and suppress downstream actionable conclusions.

Use the same normalization/event application boundary for recorded inputs and live inputs. Keep transport separate from causal consumers. Specify duplicate keys and late/corrected-bar policy; retain original data/revision provenance so a replay can reproduce the state actually available at T. Test clock skew, browser/server sleep, disconnect, rate limit, unavailable backfill, revised bars, DST, overnight/holiday transitions and contract changes. Keep owner/entitlement scoping in all cache/persistence/subscription keys.

Do not prescribe a new event platform or permanent tick database in Phase 10.5. The current local cache is reusable for bounded history, not sufficient for durable recovery. Existing Replay and Backtesting are validation consumers, not substitutes for a transport/clock/persistence service.
